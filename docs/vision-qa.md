# AI Vision and Sign Assistant: setup and QA

Updated 2026-09-07. Both photo screens are implemented. The user confirmed successful real-photo object detection on the phone. AI Vision also supports translating that same result between English, Urdu and Roman Urdu without uploading the image again. The result-language controls and phone read-aloud need the focused retest below; Sign Assistant accuracy still needs its separate checks.

## Quick retest: Urdu result toggle

1. In the backend terminal press **Ctrl+C**, then run `npm run backend:start` from the project root. Leave Expo and the existing Android USB forwarding running; no new key or package is needed.
2. Reload the app. In another terminal run `npm run backend:pair`, then enter that fresh code in **Profile → Settings → Speech setup → Connect**. Restarting the backend invalidates the previous connection.
3. Open **AI Vision**, enable **Read results aloud**, capture an ordinary object and tap **Analyze photo**. Under **Photo result**, tap **اردو**. **Expected:** the description and object names appear in Urdu Arabic script and the device reads the Urdu description. The app's menu language does not change. If the original result is already Urdu, English can be tested first instead.
4. Tap **English**, then **اردو** again. **Expected:** each translated language loads once, then switching among already viewed languages is immediate within this result session. The photo is not uploaded or analyzed again. **Roman Urdu** shows Latin-script Urdu and uses Urdu-script text for voice. **Speak again** reads whichever result is selected; **Stop speaking** stops it.
5. During a first translation, tap **Cancel**. **Expected:** the current result stays visible with its original language selected; no delayed replacement or speech. Retry that language. If translation fails, the current result is retained and the uncompleted target is not marked selected. Retake/Clear discards the old photo's translations.

The first uncached language change sends the result text to OpenAI and uses a small additional API request. Cache is in memory, not saved history. Leaving/backgrounding this screen clears the result/cache; reconnecting through Speech setup therefore requires analyzing the retained photo again.

## Set up once on this PC

1. Use the existing `server/.env` from [backend setup](stt-backend.md#setup-on-this-pc). In your editor, add the OpenAI key as `OPENAI_API_KEY`. Keep the DeepSeek and client-token settings; Deepgram is only needed for explicit speech rollback. Never paste keys into the app, chat, repository, screenshots or `EXPO_PUBLIC_*` variables. `OPENAI_VISION_MODEL` is optional and defaults to `gpt-4.1-mini`. The same OpenAI key now serves captions and both photo features, with separate speech and image models.
2. Stop your existing backend terminal with **Ctrl+C**, then run `npm run backend:start` in the project root. Leave that terminal open. `/health` checks the server process only; it does not verify any provider key or credit.
3. Reuse the running Expo web server, or run `npm run web` in a second terminal. Open the app on `http://localhost:8081`. Browser camera access requires localhost or HTTPS.
4. Open **Profile → Settings → Speech setup**, enter the new local connection code printed by the backend, and tap **Connect**. The existing captions connection is shared with both photo features; there is no separate Vision connection. Restarting the backend clears old grants. App reload/restart or one hour of elapsed grant time also requires a new connection; run `npm run backend:pair` in another terminal for a fresh one-use code.
5. Open **AI Vision**. Before analyzing, enable **Read results aloud** if you want automatic speech. It initially follows your saved **Auto speak** preference and may therefore start off.

For Android access to this still-local backend, use the USB forwarding instructions in [phone setup](live-captions-qa.md#then-test-your-android-phone). Camera capture uses Expo Camera rather than the native audio recorder. Test with the SDK-compatible app/build you already use; camera support does not establish that Expo Go supports Live Captions recording. Native builds and physical capture must be tested separately.

## Focused user QA

Use your own hand and ordinary objects, such as a cup and book. Tapping **Analyze photo** sends the captured image to OpenAI and consumes API credit. Exact wording may vary; judge whether the visible objects, hand pose and language are correct.

1. **Camera and preview:** Open AI Vision → **Take a photo** → **Allow camera** if requested. Capture a well-lit cup/book. **Expected:** a preview appears, with **Analyze photo**, **Retake photo** and **Clear photo**. Capturing alone does not upload or invent a result. Retake replaces the preview; Clear removes it.
2. **Urdu result and voice:** Save Urdu in Profile → Settings → Language. Take another clear object photo, enable **Read results aloud**, and tap **Analyze photo**. **Expected:** a brief Urdu description and visible object names in Arabic script, followed by device Urdu speech. No Hindi text. It need not list every object. **Speak again** replays the same result; **Stop speaking** stops it. The model should describe observations without claiming that navigation is safe.
3. **Other app languages:** Repeat once in English and once in Roman Urdu. **Expected:** English descriptions/speech in English; Roman Urdu descriptions in Latin script with an Urdu-script version supplied to the device voice. No Hindi output. Buttons and messages follow the app language. Initial analysis uses the saved app language. AI Vision's result-language controls then switch only that result, independently of menu language; Sign Assistant continues using the saved app language. Neither has a speech input-language selector.
4. **Voice optional:** Before analyzing a fresh photo, turn **Read results aloud** off. **Expected:** the result appears without automatic speech; **Speak again** still works. If no suitable voice is installed or browser autoplay is blocked, text remains available and playback reports an error or can be retried by tapping the button. No cloud TTS fallback is triggered.
5. **Sign Assistant:** Open Sign Assistant and photograph one clearly visible hand. Try an open palm, closed fist, thumbs-up, thumbs-down, victory/V pose and pointing up. **Expected:** it describes the observed physical pose. Then try no hand or an unclear/unsupported pose. **Expected:** an unknown/uncertain result, not an invented signed phrase. Report misclassification as an accuracy failure; do not present this as Pakistani Sign Language translation.
6. **Cancel and leave:** Tap Analyze, then **Cancel**, **Retake photo**, **Clear photo** or Back while it is working. Also leave the page during spoken playback. **Expected:** analysis or speech stops, and a late old result does not appear or start speaking. Backgrounding the app closes capture and cancels analysis/playback; returning does not automatically analyze a photo.
7. **Permission and service errors:** Deny camera permission once, then allow it in browser/device settings and retry. Separately stop your own backend and attempt Analyze. **Expected:** a clear retry/settings/connection message, usable Back/Close controls, no endless camera spinner and no fake result. Restart the backend and reconnect before continuing. Missing/invalid OpenAI configuration shows an unavailable message; no key/provider details should appear.
8. **Small screen and accessibility:** On the phone, verify camera controls, result text, Speak/Stop and Back in portrait, including Urdu mode. With a screen reader, confirm named controls and the read-aloud toggle state. On a keyboard, Space toggles read-aloud. **Expected:** readable text, reachable controls and no horizontal page overflow.

For any failure, record the test number, PC browser or phone/build, saved app language, exact in-app error and whether capture, upload, result or speech failed. Do not include API keys or connection codes. A failure message is not proof that OpenAI recognition itself failed.

## Implementation contract

The flow is **camera → local preview → explicit Analyze → authenticated backend → OpenAI image analysis → validated text → optional device TTS**. `app/vision.tsx` and `app/sign-assistant.tsx` use `src/photo-assist-screen.tsx`; `src/photo-capture.tsx` owns permission/capture, and `src/use-photo-analysis.ts` owns network/playback cancellation. `src/service-connection.ts` stores the shared, non-persisted client grant.

`POST /v1/vision/analyze` accepts exactly `{image:{base64,mimeType},language,task}`. `language` is `ur`, `en` or `roman`; `task` is `objects` or `gesture`. JPEG, PNG and WebP are accepted up to 3 MiB after base64 decoding, with header validation and a bounded JSON request. The response is `{task,description,spokenDescription,objects,gesture,uncertain}`. Object results have `gesture:null`; gesture results have an empty object list and one of `open_palm`, `closed_fist`, `thumbs_up`, `thumbs_down`, `victory`, `pointing_up`, or `unknown`.

`POST /v1/vision/translate` accepts exactly `{result,sourceLanguage,language}` with that validated object result and the same language codes. It accepts no image, URI, gesture task or extra fields. The body is capped at 32 KiB. Translation uses the same OpenAI configuration, auth/origin checks, shared Vision quotas and cancellation limits as image analysis. The response retains the result schema, uncertainty flag and object count. The prompt preserves observations, ordering, quantities and uncertainty, but semantic translation accuracy still needs human review. Each new language is derived from the original detection, never from a chain of prior translations. The client keeps the visible language/result during loading or failure and caches successful results per photo. The hook stops old playback before switching and only speaks a successful, still-current result. Result direction follows its selected language rather than the menu direction.

The server calls the OpenAI Responses API with image input, a strict JSON schema, `store:false`, a 25-second timeout, at most two active Vision calls, and twelve authorized Vision requests per minute within the existing global limit. It validates result structure, lengths and scripts before returning text. English uses Latin-script descriptions and speech; Urdu uses Arabic script; Roman Urdu uses Latin-script display text and Arabic-script speech text. No arbitrary external image URL is fetched. The app/backend do not log or permanently store the upload; native camera files may remain in temporary device cache. `store:false` is a request-storage setting, not a claim that the provider has no retention of any kind.

Device TTS is the same existing Expo Speech playback path, not speech-to-text/transcription. There is no Deepgram TTS fallback. Voice quality, availability, first-play delay and autoplay behavior depend on the device/browser. Image analysis can miss objects and hand-pose classification can be wrong. Full PSL/ASL interpretation, moving signs, sentence translation, identity inference, exact distances and safety guarantees are outside this implementation.

The backend remains loopback-bound with the existing origin/Host rules. Render hosting, public configuration and automatic public demo access are a separate deployment task.
