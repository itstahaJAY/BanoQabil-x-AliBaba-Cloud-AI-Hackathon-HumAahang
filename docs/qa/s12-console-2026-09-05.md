# S12 console follow-up — 2026-09-05

## Report and causes

User journey: Profile → Settings → change a preference → return Home. Screenshot showed normal development startup text plus three warnings:

1. Deprecated web shadow props. App theme shadows and the tab bar supplied native `shadow*` styles to React Native Web.
2. An outgoing screen had a focused button while the navigator applied `aria-hidden`. Expo Router's bundled web Screen sets that attribute during rendering; after-navigation blur alone is too late to prevent this ordering problem.
3. Home's HeroCharacter assigned both a Reanimated entry transform and an animated floating/rotation transform to one element.

## Focused fixes

- Theme selects equivalent `boxShadow` on web, preserving the existing native shadows/elevation. Tab bar uses the same platform split.
- HeroCharacter has an entry-animation wrapper and a separate floating child. Loop animations are cancelled on cleanup/reduced-motion changes. Visual design and motion are retained.
- `src/navigation.web.tsx` keeps Expo's router API but moves focus to a persistent, labelled main landmark before navigation can hide the outgoing screen. It also handles browser Back/Forward. Route completion recovers lost/hidden focus without stealing focus from a visible tab/control. Existing imperative route imports use this entry point; query-parameter changes are untouched. Native `src/navigation.tsx` simply re-exports Expo's router and renders children, leaving native focus behavior unchanged.
- No mutation observer, router internals patch, dependency change, console override or warning suppression was introduced. Ponytail guided reuse of the existing router, platform shadow APIs and animation wrappers.

## Verification

- Reproduced the web shadow and Reanimated warnings in the in-app browser before the fix. The browser-specific aria-hidden diagnostic came from the user's Chrome screenshot; the available log collector did not independently capture that browser diagnostic during the pre-fix run.
- Two navigation-focus regression assertions failed with the original no-transfer behavior, then passed with the fix. Third check covers SSR/missing root/outside-app focus. `npm test`: 25 passed. `npx tsc --noEmit`: passed.
- Web export `.expo/s12-web-check` and Android JavaScript export `.expo/s12-android-check`: passed. These are not native build/device tests.
- After a fresh reload, repeated Home → Profile → Settings → switch change → Back → Home. Verified Settings focus was on the visible `MAIN` landmark; toggling Large text retained focus on its switch; no active element had an `aria-hidden=true`/inert ancestor. Restored Large text to its original OFF value.
- Keyboard activation of the Profile tab retained actual focus on that tab. Browser Back/Forward worked. Captured no new warning/error entries after the fixed reload across these checks. Home screenshot confirmed the character, cards and tab layout remain intact.

Normal “Running application”, development-mode and performance-optimization startup messages are not failures. Node's existing module-type warning and build-tool color-environment warnings are separate from these browser issues.
